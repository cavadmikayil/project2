{{i:lock}} Giriş: rwx-dən O Yana

chmod 755-i hamı bilir. Amma paylaşılan qovluqda faylların qrupu niyə dəyişir, /tmp-də niyə başqasının faylını silə bilmirsiniz, passwd adi istifadəçiyə /etc/shadow-u necə yazdırır, və bir istifadəçiyə yalnız bir əmri root kimi necə icazə verirsiniz? Bu dərs həmin suallara cavab verir.

{{i:list-checks}} 1. Qısa Təkrar

İcazəFayldaQovluqdaRəqəm

wDəyişməkFayl yaratmaq/silmək2

{{i:lightbulb}}

Faylı silmək üçün faylın özündə yox, qovluqda w icazəsi lazımdır. Ona görə 444 icazəli faylı da qovluq sahibi silə bilər.

{{i:star}} 2. Special Bits

BitRəqəmFayldaQovluqdals-də
SUID4Proses faylın sahibinin hüququ ilə işləyir—-rwsr-xr-x
SGID2Qrupun hüququ iləYeni fayllar qovluğun qrupunu alırdrwxrwsr-x
Sticky1—Faylı yalnız sahibi silə bilərdrwxrwxrwt
 
# Komanda qovluğu: hamı yazır, fayllar "muhasibat" qrupunda qalır, başqasının faylını silmək olmur
mkdir /srv/muhasibat
chgrp muhasibat /srv/muhasibat
chmod 3770 /srv/muhasibat           # 2 (SGID) + 1 (sticky) + 770

ls -l /usr/bin/passwd               # -rwsr-xr-x root — SUID nümunəsi

# Təhlükəsizlik auditi: SUID/SGID fayllar
find / -xdev -perm /6000 -type f 2>/dev/null

Gözlənilməz SUID root fayl (məs. /tmp/.x/bash) — ciddi kompromis əlamətidir. Siyahını baseline ilə müqayisə edin.

{{i:filter}} 3. umask: Defolt İcazələr

umask            # 0022 — adətən
# Yeni fayl:   666 − 022 = 644 (rw-r--r--)
# Yeni qovluq: 777 − 022 = 755 (rwxr-xr-x)

umask 027        # fayl 640, qovluq 750 — "digərləri" heç nə görmür

Daimi etmək üçün /etc/login.defs (UMASK), ~/.bashrc və ya systemd servis faylında UMask=0027.

{{i:users}} 4. ACL: Bir Neçə İstifadəçi və Qrup

Standart icazələrdə yalnız bir sahib və bir qrup var. ACL əlavə istifadəçi və qruplara fərdi icazə verir.

setfacl -m u:auditor:rx /srv/muhasibat          # auditor yalnız oxusun
setfacl -m g:it:rwx /srv/muhasibat              # IT qrupu tam
setfacl -d -m g:it:rwx /srv/muhasibat           # default ACL — yeni fayllara da tətbiq olunur
getfacl /srv/muhasibat
setfacl -x u:auditor /srv/muhasibat             # sil
ls -l                                            # icazələrdən sonra "+" — ACL var

{{i:shield-check}} 5. sudo və sudoers

visudo -f /etc/sudoers.d/helpdesk       # HƏMİŞƏ visudo — sintaksis səhvi sudo-nu kilidləyir

# /etc/sudoers.d/helpdesk
%helpdesk  ALL=(root) /usr/bin/systemctl restart nginx, /usr/bin/journalctl -u nginx
deploy     ALL=(www-data) NOPASSWD: /usr/local/bin/deploy.sh
%admins    ALL=(ALL:ALL) ALL

sudo -l                                 # mənə nə icazə verilib?
sudo -u www-data whoami
grep sudo /var/log/auth.log             # kim nə işlətdi (RHEL: /var/log/secure)
{{i:ban}}

Qaçın: ALL=(ALL) NOPASSWD: ALL geniş istifadəçilərə; vim, less, find kimi shell aça bilən əmrlərə sudo (GTFOBins).
