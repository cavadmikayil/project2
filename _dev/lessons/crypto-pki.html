{{i:file-key}} Giriş: Kriptoqrafiya Nəyi Qoruyur?

HTTPS, VPN, Wi-Fi, SSH, parolların saxlanması, proqram yeniləmələrinin imzası — hamısı kriptoqrafiyaya əsaslanır. Onun dörd məqsədi var: məxfilik, bütövlük, autentifikasiya və inkar edilməzlik (non-repudiation).

{{i:triangle-alert}}

Qızıl qayda: öz şifrələmə alqoritminizi heç vaxt icad etməyin. Sınaqdan keçmiş standartlardan (AES, RSA, ECC, SHA-2) və etibarlı kitabxanalardan istifadə edin.

{{i:key-round}} 1. Simmetrik və Asimmetrik Şifrələmə

SimmetrikAsimmetrik
AçarBir ortaq açarAçar cütü: public + private
SürətÇox sürətliYavaş
ProblemAçarı təhlükəsiz necə paylaşmaq?Böyük həcmli məlumat üçün səmərəsiz

İstifadəMəlumatın özünü şifrələməkAçar mübadiləsi, rəqəmsal imza

Praktikada ikisi birlikdə işləyir (hibrid): asimmetrik kriptoqrafiya ilə sessiya açarı razılaşdırılır, sonra bütün trafik həmin simmetrik açarla (AES) şifrələnir. TLS və VPN-lər məhz belə işləyir.

{{i:fingerprint}} 2. Hash Funksiyaları

Hash istənilən ölçülü məlumatdan sabit uzunluqlu "barmaq izi" yaradır. Geri çevrilmir (şifrələmə deyil!) və məlumatda bir bit dəyişəndə nəticə tamamilə dəyişir.

echo -n "salam" | sha256sum
# b1a3... (64 hex simvol = 256 bit)

sha256sum ubuntu-24.04.iso            # yüklənmiş faylın bütövlüyünü yoxla
Get-FileHash .\setup.exe -Algorithm SHA256   # Windows
AlqoritmVəziyyət
MD5, SHA-1Sındırılıb (collision) — təhlükəsizlik üçün istifadə etməyin
SHA-256, SHA-3Bütövlük və imza üçün standart
bcrypt, scrypt, Argon2Parolları saxlamaq üçün — qəsdən yavaş və "duzlu" (salt)
{{i:lightbulb}}

Salt — hər parola əlavə olunan təsadüfi dəyər. Onsuz eyni parollar eyni hash verir və əvvəlcədən hesablanmış cədvəllərlə (rainbow table) tez tapılır.

{{i:pen-line}} 3. Rəqəmsal İmza

  1. Göndərən sənədin hash-ını hesablayır və onu öz private açarı ilə imzalayır.

  2. Alan tərəf imzanı göndərənin public açarı ilə yoxlayır və sənədin hash-ı ilə müqayisə edir.

  3. Uyğun gəlirsə: sənəd dəyişdirilməyib (bütövlük) və onu yalnız private açarın sahibi imzalaya bilərdi (autentifikasiya, inkar edilməzlik).

Harada: proqram yeniləmələri (code signing), IOS image-ların imzası, email (S/MIME), PDF, Git commit-lər, DKIM.

{{i:badge-check}} 4. PKI və Sertifikatlar

Public açarın həqiqətən bank.az-a məxsus olduğunu necə bilirik? Sertifikat — etibarlı mərkəzin (CA) "bu açar bu adın sahibinindir" deyə imzaladığı sənəddir.

Root CA   (brauzer/OS-da əvvəlcədən etibarlı siyahıda)
   └── Intermediate CA   (Root tərəfindən imzalanıb)
          └── bank.az sertifikatı   (Intermediate tərəfindən imzalanıb)
                 subject: CN=bank.az, SAN: bank.az, www.bank.az
                 etibarlıdır: 2026-01-10 → 2026-04-10
                 public key: ...
{{i:link}}

Chain of trust: server intermediate sertifikatı da göndərməlidir — əks halda bəzi cihazlarda "untrusted" xətası.

{{i:ban}}

Revocation: oğurlanmış açarın sertifikatı ləğv olunur — CRL və OCSP ilə yoxlanılır.

{{i:building}}

Daxili PKI: şirkətlər öz CA-larını qurur (AD Certificate Services) — 802.1X, VPN, daxili saytlar üçün.

{{i:lock}} 5. TLS Handshake (sadələşdirilmiş, TLS 1.3)

  1. ClientHello: brauzer dəstəklədiyi alqoritmləri və açar mübadiləsi üçün öz hissəsini göndərir.

  2. ServerHello: server alqoritmi seçir, öz açar hissəsini, sertifikatını və imzanı göndərir.

  3. Brauzer sertifikatı yoxlayır: CA etibarlıdırmı, ad uyğundurmu, vaxtı keçməyibmi.

  4. Hər iki tərəf (ECDHE) eyni sessiya açarını hesablayır — açar şəbəkədə heç vaxt göndərilmir. Bundan sonra trafik AES-GCM/ChaCha20 ilə şifrələnir.

{{i:shield-check}}

Forward secrecy: hər sessiya üçün müvəqqəti açar yaradıldığından, serverin private açarı gələcəkdə oğurlansa belə, əvvəl yazılmış trafik açıla bilməz. SSL 3.0, TLS 1.0/1.1 söndürülməli, TLS 1.2 və 1.3 istifadə olunmalıdır.

{{i:terminal}} 6. OpenSSL ilə Praktika

# Private açar və CSR (sertifikat sorğusu) yaratmaq
openssl req -new -newkey rsa:2048 -nodes -keyout site.key -out site.csr -subj "/CN=intranet.example.az"

# Sertifikatın məzmununu oxumaq
openssl x509 -in site.crt -noout -subject -issuer -dates -ext subjectAltName

# Saytın sertifikat zəncirini yoxlamaq
openssl s_client -connect example.az:443 -servername example.az -showcerts </dev/null

# Faylı AES-256 ilə şifrələmək və açmaq
openssl enc -aes-256-cbc -pbkdf2 -salt -in secret.txt -out secret.enc
openssl enc -d -aes-256-cbc -pbkdf2 -in secret.enc -out secret.txt

Private açar (site.key) heç vaxt paylaşılmır, email-lə göndərilmir və git-ə əlavə olunmur. CA-ya yalnız CSR göndərilir.
