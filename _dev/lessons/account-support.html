{{i:key-round}} Giriş: Ən Çox Müraciət — Ən Böyük Risk

"Parolumu unutmuşam" və "hesabım kilidlənib" helpdesk müraciətlərinin əhəmiyyətli hissəsini təşkil edir. Eyni zamanda bu, hücumçuların sevimli yoludur: özünü işçi kimi təqdim edib parolu sıfırlatmaq (social engineering). Buna görə sürət qədər düzgün kimlik yoxlaması da vacibdir.

{{i:user-check}} 1. Zəng Edən Həqiqətən Odurmu?

{{i:phone}}

Geri zəng: istifadəçinin sistemdə qeydiyyatda olan nömrəsinə zəng edin — zəng gələn nömrəyə yox.

{{i:users}}

Rəhbər təsdiqi: həssas hesablar üçün birbaşa rəhbərin ticket-də təsdiqi.

{{i:id-card}}

Şəxsən: vəsiqə ilə helpdesk-ə gəlmək.

{{i:smartphone}}

Self-service (SSPR): istifadəçi MFA ilə parolunu özü sıfırlayır — ən yaxşısı.

{{i:shield-alert}}

Qırmızı bayraqlar: təcili təzyiq ("direktor gözləyir!"), rəhbər adından zəng, yeni parolun başqa nömrəyə/email-ə göndərilməsi xahişi, MFA-nın "müvəqqəti" söndürülməsi istəyi. Belə hallarda proseduru sürətləndirməyin — əksinə, yavaşladın.

{{i:refresh-cw}} 2. Parol Sıfırlama

  1. dsa.msc → istifadəçini tapın → sağ klik → Reset Password.

  2. User must change password at next logon — işarələyin: müvəqqəti parolu yalnız istifadəçi bilsin.

  3. Hesab kilidlidirsə, Unlock the user's account.

  4. Müvəqqəti parolu təhlükəsiz kanalla verin — email-lə yox (hesab onsuz da açılmır).

$tmp = Read-Host -AsSecureString "Muveqqeti parol"
Set-ADAccountPassword -Identity aysel -Reset -NewPassword $tmp
Set-ADUser -Identity aysel -ChangePasswordAtLogon $true
Unlock-ADAccount -Identity aysel

Get-ADUser aysel -Properties LockedOut, PasswordLastSet, PasswordExpired, BadLogonCount, Enabled

Microsoft 365 / Entra ID admin mərkəzi → Users → istifadəçi → Reset password. Hibrid mühitdə (AD Connect) parol AD-də dəyişdirilir və sinxronlaşır; SSPR aktivdirsə istifadəçi bunu aka.ms/sspr ünvanında özü edir.

{{i:lock}} 3. Hesab Təkrar-Təkrar Kilidlənir

Kilidi açırsınız, 10 dəqiqə sonra yenidən kilidlənir. Səbəb demək olar ki, həmişə köhnə parolu saxlayan bir cihaz və ya xidmətdir.

MənbəHarada yoxlamaq
Telefondakı köhnə email/Wi-Fi profiliMobil cihazda parolu yeniləmək
Windows Credential Managercontrol keymgr.dll — köhnə parolları silmək
Xəritələnmiş şəbəkə diskiBaşqa parolla qoşulmuş disk
Planlı tapşırıq və ya xidmətİstifadəçi hesabı ilə işləyən task/service
Açıq qalmış RDP sessiyasıBaşqa serverdə köhnə sessiya
 
# PDC Emulator-da 4740 hadisəsi: hesabın hansı kompüterdən kilidləndiyi
$pdc = (Get-ADDomain).PDCEmulator
Get-WinEvent -ComputerName $pdc -FilterHashtable @{LogName='Security'; Id=4740} |
  Where-Object { $_.Properties[0].Value -eq 'aysel' } |
  Select TimeCreated, @{n='Computer';e={$_.Properties[1].Value}}

Event 4740 "hesab kilidləndi" hadisəsidir və "Caller Computer Name" sahəsi səhv parol göndərən cihazı göstərir. Microsoft-un pulsuz Account Lockout Status aləti də bunu edir.

{{i:repeat}} 5. Joiner – Mover – Leaver

{{i:user-plus}} Joiner (yeni işçi)

HR müraciəti ilə hesab, şablon qruplar, lisenziya, email, avadanlıq — ilk iş günündən əvvəl hazır.

{{i:arrow-left-right}} Mover (vəzifə dəyişikliyi)

Yeni icazələr əlavə olunur, köhnələri çıxarılır — yoxsa icazələr illərlə yığılır (privilege creep).

{{i:user-minus}} Leaver (işdən çıxma)

Son gün hesab söndürülür (silinmir), sessiyalar ləğv edilir, mailbox rəhbərə ötürülür, avadanlıq qaytarılır.
