{{i:bot}} Giriş: CLI-dan Koda

Şəbəkə mühəndisinin işi onilliklər boyu eyni olub: cihaza SSH, əmrləri yaz, show run ilə yoxla, növbəti cihaz. 10 cihazda bu işləyir, 500 cihazda isə səhvlər, uyğunsuz konfiqurasiyalar və gecə növbələri deməkdir. Network automation — təkrarlanan şəbəkə işlərini proqram, API və şablonlarla etmək deməkdir. CCNA 200-301 imtahanının 10%-i məhz bu mövzudur.

{{i:layers}} 2. Management, Control və Data Plane

{{i:settings}} Management plane

Cihazı idarə etmək: SSH, SNMP, API, NETCONF. Avtomatlaşdırma burada işləyir.

{{i:brain}} Control plane

Qərar vermək: OSPF, BGP, STP, ARP — routing və switching cədvəllərini qurmaq.

{{i:zap}} Data plane

Paketləri faktiki ötürmək: cədvələ baxıb frame/paketi portdan göndərmək (ASIC).

Ənənəvi şəbəkədə hər cihazın öz control plane-i var. SDN (Software-Defined Networking) control plane-i mərkəzi kontrollerə çıxarır: kontroller bütün şəbəkəni görür və cihazlara southbound API ilə göstəriş verir, tətbiqlər isə kontrollerlə northbound API (adətən REST) ilə danışır.

{{i:flag}} 5. Haradan Başlamaq

  1. Read-only ilə başlayın: bütün cihazlardan show version toplayıb inventar cədvəli yaratmaq — heç nəyi poza bilməzsiniz.

  2. Konfiqurasiya backup-ı: hər gecə show run-ı git-ə yazmaq — dəyişikliklər avtomatik görünür.

  3. Uyğunluq yoxlaması: "hər cihazda NTP, AAA və banner varmı?" hesabatı.

  4. Kiçik dəyişikliklər: VLAN, description, SNMP community — əvvəlcə lab-da.

  5. Source of truth + şablonlar: konfiqurasiyanın tamamilə məlumatdan yaradılması.
