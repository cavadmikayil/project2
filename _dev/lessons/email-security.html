{{i:mail-warning}} Giriş: Hücumların Əsas Qapısı

Ransomware və məlumat sızmalarının çox hissəsi bir email ilə başlayır: saxta giriş səhifəsi, zərərli əlavə və ya "direktordan" təcili ödəniş tapşırığı. Texniki filtrlər çoxunu tutur, amma hamısını yox — son müdafiə xətti diqqətli istifadəçidir.

{{i:scan-search}} 1. Phishing Əlamətləri

{{i:at-sign}}

Göndərən ünvan: görünən ad "Bank ASC", ünvan isə support@bank-az-secure.com; rn ilə m kimi hərf oyunları.

{{i:timer}}

Təcililik və qorxu: "24 saat ərzində təsdiqləməsəniz hesab bloklanacaq".

{{i:link}}

Link: üzərinə gətirəndə (klikləmədən) göstərilən ünvan mətnlə uyğun gəlmir.

{{i:paperclip}}

Əlavələr: gözlənilməz .zip, .iso, .html, makrolu Office faylı, "faktura.pdf.exe".

{{i:banknote}}

Pul və ya məlumat istəyi: bank rekvizitlərinin dəyişməsi, hədiyyə kartı, parol.

{{i:qr-code}}

QR kod (quishing): email filtrindən yan keçmək üçün linki QR-a gizlədirlər.

{{i:badge-check}} 3. SPF, DKIM və DMARC

SMTP protokolu göndərəni yoxlamır — istənilən server "From: ceo@example.az" yaza bilər. Bu üç DNS qeydi domeninizin adından saxta məktubların qarşısını alır.

MexanizmNəyi yoxlayırDNS qeydi nümunəsi
SPFBu IP domen adından məktub göndərməyə icazəlidirmi?v=spf1 include:spf.protection.outlook.com -all
DKIMMəktub domenin private açarı ilə imzalanıb və yolda dəyişməyibmi?selector1._domainkey TXT/CNAME — public açar
DMARCSPF/DKIM uyğun gəlməzsə nə etməli + hesabatlar_dmarc TXT: v=DMARC1; p=reject; rua=mailto:dmarc@example.az

  1. SPF və DKIM-i bütün göndərən xidmətlər üçün qurun (email, CRM, marketinq platforması).

  2. DMARC-ı p=none ilə başladın və hesabatları izləyin — kim sizin adınızdan göndərir?

  3. Tədricən p=quarantine, sonra p=reject.

dig example.az TXT +short                 # SPF
dig _dmarc.example.az TXT +short          # DMARC
dig selector1._domainkey.example.az TXT +short

{{i:file-search}} 4. Başlıq (Header) Analizi

Outlook-da "View message source / Message details", Gmail-də "Show original". Əsas sahələr:

From: "Direktor" <ceo@example.az>
Reply-To: ceo.example.az@gmail.com           ← cavab başqa yerə gedir!
Return-Path: <bounce@mailer-xyz.top>
Authentication-Results: mx.example.az;
   spf=fail (sender IP is 185.x.x.x) smtp.mailfrom=example.az;
   dkim=none;
   dmarc=fail action=quarantine header.from=example.az
Received: from unknown (185.x.x.x) ...
{{i:circle-x}}

spf/dkim/dmarc=fail — domen adından saxta göndəriş.

{{i:reply}}

Reply-To fərqlidir — BEC hücumlarının klassik əlaməti.

{{i:route}}

Received zənciri aşağıdan yuxarı oxunur — məktubun real mənşəyi.

{{i:siren}} 5. Şübhəli Məktub — Nə Etməli?

{{i:flag}} İstifadəçi

Klikləməyin, cavab verməyin, "Report phishing" düyməsi ilə bildirin. Kliklədinizsə və ya parol yazdınızsa — dərhal IT-yə deyin; utanmaq itirilən vaxtdan ucuzdur.

{{i:shield-check}} IT / SOC

Eyni məktubu bütün mailbox-lardan silmək, göndərəni və domeni bloklamaq, klikləyənlərin parolunu dəyişib sessiyalarını ləğv etmək, log-larda giriş cəhdlərini yoxlamaq.

{{i:lightbulb}}

BEC-ə qarşı proses: bank rekvizitlərinin dəyişməsi və təcili ödəniş tələbi həmişə başqa kanalla (məlum telefon nömrəsinə zəng) təsdiqlənməlidir. Bu sadə qayda milyonlarla manat itkinin qarşısını alır.
