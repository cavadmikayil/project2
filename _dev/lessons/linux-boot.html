{{i:power}} Giriş: Düymədən Login-ə Qədər

Server açılmırsa, harada ilişdiyini bilmək lazımdır: firmware, bootloader, kernel, yoxsa servislər? Bu dərs boot zəncirini, öz systemd servisinizi yazmağı, cron əvəzinə timer istifadəsini və açılmayan sistemi bərpa etməyi öyrədir. (systemctl əsasları üçün Server kateqoriyasındakı "systemd, Loglar və SSH" dərsinə baxın.)

{{i:list-ordered}} 1. Boot Ardıcıllığı

  1. Firmware (UEFI/BIOS): POST, boot cihazının seçimi; UEFI-də /boot/efi bölməsindən EFI faylı.

  2. Bootloader (GRUB 2): menyu, kernel və parametrləri seçir.

  3. Kernel + initramfs: hardware driver-ləri, root fayl sistemini tapıb mount edir (LVM, RAID, şifrələmə).

  4. systemd (PID 1): default.target-ə çatmaq üçün unit-ləri paralel başladır.

  5. Login: getty (konsol) və ya sshd, qrafik sistemdə display manager.

systemd-analyze                         # boot nə qədər çəkdi
systemd-analyze blame | head            # ən yavaş servislər
systemd-analyze critical-chain
journalctl -b -p err                    # bu boot-un xətaları
journalctl -b -1                        # əvvəlki boot (Storage=persistent olmalıdır)
cat /proc/cmdline                       # kernel parametrləri

{{i:file-cog}} 3. Öz Servisini Yazmaq

# /etc/systemd/system/portal-api.service
[Unit]
Description=Portal API
After=network-online.target postgresql.service
Wants=network-online.target

[Service]
Type=simple
User=portal
WorkingDirectory=/opt/portal
EnvironmentFile=/etc/portal/api.env
ExecStart=/opt/portal/.venv/bin/gunicorn -b 127.0.0.1:8000 app:app
Restart=on-failure
RestartSec=5
# Təhlükəsizlik
NoNewPrivileges=true
ProtectSystem=strict
ReadWritePaths=/var/lib/portal
PrivateTmp=true

[Install]
WantedBy=multi-user.target
systemctl daemon-reload
systemctl enable --now portal-api
systemctl status portal-api
journalctl -u portal-api -f
systemctl edit nginx            # paylanma faylına toxunmadan override (drop-in)
systemd-analyze security portal-api    # təhlükəsizlik balı

/usr/lib/systemd/system/ — paketlərin faylları (yeniləmədə üzərinə yazılır); /etc/systemd/system/ — sizin fayllar və override-lar, üstünlük təşkil edir.

{{i:alarm-clock}} 4. Timer-lər: cron-un Müasir Əvəzi

# /etc/systemd/system/db-backup.service
[Unit]
Description=PostgreSQL backup
[Service]
Type=oneshot
User=postgres
ExecStart=/usr/local/bin/db-backup.sh

# /etc/systemd/system/db-backup.timer
[Unit]
Description=Gecəlik DB backup
[Timer]
OnCalendar=*-*-* 02:30:00
RandomizedDelaySec=10m
Persistent=true            # server söndürülü idisə, açılanda qaçırılanı işlət
[Install]
WantedBy=timers.target

systemctl enable --now db-backup.timer
systemctl list-timers
systemd-analyze calendar "Mon..Fri 08:00"   # ifadəni yoxla

Üstünlükləri: nəticə journal-da, uğursuzluq systemctl --failed-də görünür, asılılıqlar və resurs limitləri, qaçırılan işlərin icrası.
