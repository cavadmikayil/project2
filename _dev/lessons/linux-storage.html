{{i:database}} Giriş: "Diskə Yer Əlavə Et" Tapşırığı

Server administratorunun ən tez-tez aldığı sorğulardan biri: "/var doldu, yer artırın". Fiziki bölmələrlə bu, çətin və riskli işdir; LVM ilə isə sistemi dayandırmadan, bir neçə əmrlə edilir. Bu dərs diskdən fayl sisteminə qədər bütün zənciri göstərir.

{{i:hard-drive}} Disk

/dev/sda, /dev/nvme0n1, /dev/vdb (VM).

{{i:layers}} Bölmə / LVM

/dev/sda1 və ya /dev/vg_data/lv_app.

{{i:folder}} Fayl sistemi

ext4 və ya XFS, mount nöqtəsi ilə qovluq ağacına qoşulur.

{{i:hard-drive}} 1. Bölmə və Fayl Sistemi

lsblk                                   # yeni disk: sdb, bölməsiz
parted /dev/sdb --script mklabel gpt mkpart data 0% 100%
mkfs.xfs /dev/sdb1                      # və ya: mkfs.ext4 -L data /dev/sdb1
mkdir -p /data && mount /dev/sdb1 /data
blkid /dev/sdb1                         # UUID → /etc/fstab-a
ext4XFS
DefoltDebian, UbuntuRHEL, Rocky, Alma
BöyütməkOnlineOnline
KiçiltməkOffline (unmount)Mümkün deyil
Böyük fayllar və paralel I/OYaxşıÇox yaxşı

{{i:layers-3}} 2. LVM: Çevik Disk İdarəetməsi

  1. PV (Physical Volume): LVM üçün hazırlanmış disk və ya bölmə.

  2. VG (Volume Group): bir neçə PV-nin birləşdiyi yer hovuzu.

  3. LV (Logical Volume): VG-dən ayrılan "virtual bölmə" — üzərində fayl sistemi yaradılır.

pvcreate /dev/sdb /dev/sdc
vgcreate vg_data /dev/sdb /dev/sdc
lvcreate -n lv_app -L 200G vg_data
lvcreate -n lv_logs -l 100%FREE vg_data
mkfs.xfs /dev/vg_data/lv_app

pvs; vgs; lvs                          # qısa baxış
lvdisplay /dev/vg_data/lv_app          # ətraflı

lvcreate -s -n snap_app -L 20G /dev/vg_data/lv_app   # snapshot — yeniləmədən əvvəl

{{i:maximize-2}} 3. Yeri Artırmaq (Fasiləsiz)

pvcreate /dev/sdd
vgextend vg_data /dev/sdd
lvextend -r -L +100G /dev/vg_data/lv_app      # -r: fayl sistemini də böyüt
df -h /data
echo 1 > /sys/class/block/sdb/device/rescan     # kernel yeni ölçünü görsün
growpart /dev/sdb 1                              # bölməni böyüt (cloud-guest-utils)
pvresize /dev/sdb1
lvextend -r -l +100%FREE /dev/vg_data/lv_app
{{i:lightbulb}}

-r olmadan LV böyüyür, amma fayl sistemi köhnə ölçüdə qalır; onda əl ilə: XFS üçün xfs_growfs /data, ext4 üçün resize2fs /dev/vg_data/lv_app.

{{i:copy}} 4. Software RAID: mdadm

mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb /dev/sdc   # RAID 1
cat /proc/mdstat                         # sinxronizasiya vəziyyəti
mdadm --detail /dev/md0
mdadm --detail --scan >> /etc/mdadm/mdadm.conf    # RHEL: /etc/mdadm.conf
update-initramfs -u                      # (Debian/Ubuntu)

# Disk sıradan çıxdı
mdadm /dev/md0 --fail /dev/sdc --remove /dev/sdc
# ... yeni disk quraşdırılır ...
mdadm /dev/md0 --add /dev/sdd            # rebuild avtomatik başlayır

RAID backup deyil: səhvən silinmiş fayl hər iki diskdən eyni anda silinir. Hardware RAID-də vəziyyət vendor aləti ilə (storcli, ssacli) izlənir.

{{i:heart-pulse}} 5. Swap və Disk Sağlamlığı

# 4 GB swap faylı
fallocate -l 4G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
swapon --show; free -h
sysctl vm.swappiness=10                # serverlərdə swap-a daha gec keç

# Sağlamlıq
smartctl -H /dev/sda                   # S.M.A.R.T. nəticəsi
smartctl -a /dev/sda | grep -Ei "reallocated|pending|wear"
nvme smart-log /dev/nvme0
dmesg -T | grep -Ei "i/o error|ata[0-9]"
{{i:triangle-alert}}

Reallocated/pending sektorların sayı artırsa, disk ölmək üzrədir — dərhal backup və dəyişdirmə planı.
