{{i:layers}} Giriş: Niyə Qatlı Model?

OSI (Open Systems Interconnection) modeli şəbəkə rabitəsini 7 məntiqi qata bölən istinad modelidir. Hər qat öz vəzifəsini yerinə yetirir və yalnız qonşu qatlarla əlaqə saxlayır. Bu bölgü protokolları müstəqil inkişaf etdirməyə, cihazların rolunu anlamağa və ən əsası — problemləri sistemli şəkildə, qat-qat aradan qaldırmağa kömək edir. Real şəbəkələrdə isə daha sadə, 4 qatlı TCP/IP modeli işləyir.

{{i:puzzle}} Modullu dizayn

Wi-Fi-dan Ethernet-ə keçmək HTTP-ni dəyişmir — yalnız aşağı qatlar dəyişir.

{{i:languages}} Ortaq dil

"L2 problemi", "L7 firewall" — mühəndislər qat nömrələri ilə danışır.

{{i:search-check}} Troubleshooting

Qat-qat yoxlama təxminləri aradan qaldırır və vaxta qənaət edir.

{{i:list-ordered}} 1. OSI Modelinin 7 Qatı

Yadda saxlamaq üçün (7 → 1): "All People Seem To Need Data Processing".

7

Application (Tətbiq) — istifadəçi proqramlarına şəbəkə xidməti. HTTP, HTTPS, DNS, FTP, SMTP, SSH, DHCP · PDU: Data

6

Presentation (Təqdimat) — məlumatın formatı, şifrələmə, sıxılma. TLS/SSL, JPEG, ASCII · PDU: Data

5

Session (Sessiya) — sessiyaların açılması, idarəsi və bağlanması. NetBIOS, RPC · PDU: Data

4

Transport (Nəqliyyat) — uç-uca çatdırılma, port nömrələri, seqmentləşdirmə. TCP, UDP · PDU: Segment / Datagram

3

Network (Şəbəkə) — məntiqi ünvanlama və marşrutlaşdırma. IPv4, IPv6, ICMP, OSPF · Cihaz: Router · PDU: Packet

2

Data Link (Kanal) — fiziki ünvanlama (MAC), çərçivələmə, xəta aşkarlama. Ethernet, 802.1Q, STP, PPP · Cihaz: Switch · PDU: Frame

1

Physical (Fiziki) — bitlərin kabel və ya radio ilə ötürülməsi. Kabel, konnektor, siqnal, Wi-Fi radio · Cihaz: Hub, kabel · PDU: Bit

{{i:handshake}} TCP

Bağlantı yönümlü (3-way handshake: SYN → SYN-ACK → ACK), çatdırılmanı təsdiqləyir, itən seqmentləri yenidən göndərir. HTTP, SSH, FTP üçün.

{{i:zap}} UDP

Bağlantısız, təsdiqsiz, lakin sürətli və az yüklü. DNS sorğuları, DHCP, VoIP, video axını üçün.

{{i:package}} 3. Enkapsulyasiya

Göndərən tərəfdə məlumat yuxarıdan aşağıya enərkən hər qat öz başlığını (header) əlavə edir; qəbul edən tərəfdə isə başlıqlar aşağıdan yuxarıya doğru çıxarılır (de-enkapsulyasiya).

Data                                         ← Application
[TCP/UDP header | Data]                      ← Segment  (L4: portlar)
[IP header | TCP header | Data]              ← Packet   (L3: IP ünvanları)
[Eth header | IP | TCP | Data | FCS trailer] ← Frame    (L2: MAC ünvanları)
0101101001110...                             ← Bits     (L1)

Router paketi ötürərkən L2 başlığını hər hop-da yenidən yazır (yeni MAC-lar), L3 başlığındakı IP ünvanları isə (NAT olmadıqda) dəyişmir.

{{i:search-check}} 4. Qat-qat Troubleshooting (Aşağıdan Yuxarı)

Problem axtararkən ən etibarlı üsul bottom-up yanaşmasıdır: əvvəlcə fiziki bağlantını, sonra MAC/VLAN, sonra IP və marşrutu, ən sonda isə tətbiqi yoxlayın.

show interfaces status
show interfaces GigabitEthernet0/1
show mac address-table
show vlan brief
show cdp neighbors

Port up/down statusu, speed/duplex uyğunsuzluğu, CRC xətaları (L1), MAC cədvəli, VLAN təyinatı və qonşu cihazlar (L2).

show ip interface brief
show ip route
show arp
ping 192.168.1.1
traceroute 8.8.8.8

İnterfeys IP-ləri, marşrut cədvəli, ARP (IP↔MAC), əlçatanlıq (ICMP) və yolun hansı hop-da kəsildiyi.

show access-lists
show ip nat translations
telnet 192.168.1.10 80
show ip dhcp binding
show control-plane host open-ports

Portları bloklayan ACL-lər, NAT tərcümələri, müəyyən TCP portunun açıq olub-olmaması, DHCP icarələri və cihazın özündə açıq portlar.
