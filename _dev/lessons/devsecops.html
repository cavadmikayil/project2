Ənənəvi modeldə təhlükəsizlik komandası release-dən bir həftə əvvəl pentest edir və 40 problem tapır — release ya gecikir, ya da problemlər "sonra düzəldilər" deyə çıxarılır. {{i:workflow}} 3. Pipeline Nümunəsi

# .github/workflows/security.yml
name: Security
on: [pull_request]
permissions:
  contents: read
jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }

      - name: Secret-lər
        run: docker run --rm -v "$PWD:/repo" zricethezav/gitleaks:latest detect --source /repo --redact

      - name: SAST (Semgrep)
        run: pipx run semgrep scan --config auto --error

      - name: Asılılıqlar və IaC (Trivy)
        run: |
          docker run --rm -v "$PWD:/src" aquasec/trivy:latest fs --scanners vuln,misconfig \
            --severity HIGH,CRITICAL --exit-code 1 /src

      - name: Image skanı
        run: |
          docker build -t app:${{ github.sha }} .
          docker run --rm -v /var/run/docker.sock:/var/run/docker.sock aquasec/trivy:latest \
            image --severity CRITICAL --exit-code 1 app:${{ github.sha }}

--exit-code 1 — yalnız HIGH/CRITICAL tapıntıda pipeline dayanır. Başlanğıcda "yalnız xəbər ver" rejimi ilə başlayıb, mövcud problemlər təmizləndikcə sərtləşdirin.

{{i:package-search}} 4. Software Supply Chain

SolarWinds, Log4Shell, xz-utils — hücumlar artıq birbaşa sizə yox, istifadə etdiyiniz kitabxana və alətlərə yönəlir.

{{i:list-checks}}

SBOM: Software Bill of Materials — artefaktın bütün komponentlərinin siyahısı (SPDX, CycloneDX). Yeni CVE çıxanda "biz təsirlənirikmi?" suala dəqiqələrlə cavab.

{{i:pen-line}}

İmzalama: Sigstore / cosign ilə image imzalanır, cluster yalnız imzalı image-ları qəbul edir.

{{i:pin}}

Pinning: asılılıqları lock faylı ilə, GitHub action-ları commit SHA ilə sabitləyin.

{{i:chart-no-axes-column-increasing}}

SLSA: build prosesinin etibarlılıq səviyyələri — kim, harada, hansı mənbədən qurdu (provenance).
