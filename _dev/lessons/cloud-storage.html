{{i:hard-drive}} Giriş: Hansı Məlumat, Harada?

Cloud-da storage seçimi həm performansa, həm də hesaba birbaşa təsir edir. Eyni 10 TB məlumat yanlış class-da saxlananda ayda yüzlərlə dollar artıq ödənilir, yanlış icazə ilə saxlananda isə xəbərlərə düşən məlumat sızmasına çevrilir.

{{i:gauge}} Performance

IOPS, throughput və latency — verilənlər bazası üçün kritikdir.

{{i:shield-check}} Durability

Məlumatın itməmə ehtimalı. S3 və Blob illik 99.999999999% (11 doqquz) vəd edir.

{{i:activity}} Availability

Məlumata istənilən an çata bilmək. Durability-dən fərqlidir: məlumat itməyib, amma müvəqqəti əlçatmaz ola bilər.

{{i:recycle}} 3. Lifecycle Policy

Log və backup-lar üçün class keçidlərini əl ilə yox, qayda ilə edin.

{
  "Rules": [{
    "ID": "logs-retention",
    "Filter": { "Prefix": "logs/" },
    "Status": "Enabled",
    "Transitions": [
      { "Days": 30,  "StorageClass": "STANDARD_IA" },
      { "Days": 90,  "StorageClass": "GLACIER_IR" },
      { "Days": 365, "StorageClass": "DEEP_ARCHIVE" }
    ],
    "Expiration": { "Days": 2555 },
    "NoncurrentVersionExpiration": { "NoncurrentDays": 30 }
  }]
}

aws s3api put-bucket-lifecycle-configuration --bucket cavad-logs \
  --lifecycle-configuration file://lifecycle.json

2555 gün ≈ 7 il — maliyyə log-ları üçün tipik qanuni saxlama müddəti. Köhnə versiyalar isə 30 gündən sonra silinir.

{{i:lock}} 4. Məlumatı Qorumaq

{{i:eye-off}}

Block Public Access: hesab səviyyəsində aktiv saxlayın. Public fayl lazımdırsa — CloudFront/CDN arxasından verin.

{{i:history}}

Versioning: silinən və ya üzərinə yazılan fayl geri qaytarılır — ransomware və səhv əmrə qarşı.

{{i:lock-keyhole}}

Object Lock / Immutable storage: WORM — müəyyən müddət heç kim, hətta admin də silə bilməz. Backup üçün idealdır.

{{i:key-round}}

Encryption at rest: defolt olaraq aktivdir; KMS / Key Vault-da öz açarınız (CMK) ilə açara nəzarət sizdədir.

{{i:link}}

Pre-signed URL / SAS token: faylı public etmədən 15 dəqiqəlik müvəqqəti link vermək.

{{i:copy}}

Replication: başqa regiona və ya ayrıca backup hesabına avtomatik nüsxə — 3-2-1 qaydasının "1 kənarda" hissəsi.

{{i:terminal}} 5. Praktika

aws s3api put-bucket-versioning --bucket cavad-backup --versioning-configuration Status=Enabled
aws s3api put-public-access-block --bucket cavad-backup \
  --public-access-block-configuration BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true

aws s3 cp db-2027-01-15.sql.gz s3://cavad-backup/db/ --storage-class STANDARD_IA
aws s3 presign s3://cavad-backup/db/db-2027-01-15.sql.gz --expires-in 900
aws s3api list-object-versions --bucket cavad-backup --prefix db/
az storage account blob-service-properties update -g rg-backup \
  --account-name stcavadbackup --enable-versioning true --enable-delete-retention true --delete-retention-days 14

az storage blob upload --account-name stcavadbackup -c db -f db-2027-01-15.sql.gz \
  --tier Cool --auth-mode login

az storage blob generate-sas --account-name stcavadbackup -c db -n db-2027-01-15.sql.gz \
  --permissions r --expiry 2027-01-15T12:00Z --as-user --auth-mode login --full-uri
