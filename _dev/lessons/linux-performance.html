{{i:gauge}} Giriş: "Server Yavaşdır"

Bu şikayətin arxasında dörd resursdan biri dayanır: CPU, yaddaş, disk I/O və ya şəbəkə. Təcrübəli administrator təxmin etmir — Brendan Gregg-in USE metodunu tətbiq edir: hər resurs üçün Utilization (nə qədər məşğuldur), Saturation (növbə varmı), Errors (xəta varmı).

{{i:timer}} 1. İlk 60 Saniyə

uptime                     # load average: 1, 5, 15 dəqiqə — artır, yoxsa azalır?
dmesg -T | tail            # OOM killer, disk xətaları, NIC problemləri
vmstat 1 5                 # r (CPU növbəsi), si/so (swap), wa (I/O gözləmə)
mpstat -P ALL 1 3          # CPU-lar arasında paylanma — bir nüvə 100%-dirmi?
pidstat 1 3                # hansı proses CPU yeyir
iostat -xz 1 3             # disk: %util, await, aqu-sz
free -h                    # RAM və swap
sar -n DEV 1 3             # şəbəkə trafiki
sar -n TCP,ETCP 1 3        # TCP bağlantıları və retransmit-lər
top                        # ümumi mənzərə

vmstat, mpstat, iostat, pidstat, sar — sysstat paketindədir. Serverlərə əvvəlcədən quraşdırın; sar keçmiş günlərin məlumatını da saxlayır.

{{i:cpu}} 2. CPU və Load Average

{{i:calculator}}

Load average — işləyən + növbədə gözləyən (+ D vəziyyətində olan) proseslərin orta sayı. 8 nüvəli serverdə 8 — tam yük, 16 — ciddi növbə.

{{i:hard-drive}}

Load yüksək, CPU boşdur? — proseslər D vəziyyətində disk/NFS gözləyir. top-da yüksək wa.

{{i:user}}

us — tətbiq kodu, sy — kernel (çoxlu syscall, şəbəkə), st — steal: VM-də hypervisor CPU verməyib (qonşu VM-lər).

GörüntüEhtimal
Bir proses 100% (bir nüvə)Tək axınlı tətbiq, sonsuz dövr
Yüksək syHəddən çox kiçik I/O, context switch, şəbəkə yükü
Yüksək st (>10%)Host həddən çox yüklənib — VM-i başqa hosta köçürün
Çoxlu qısa ömürlü proseslərCron/skriptlər hər saniyə fork edir — execsnoop

{{i:memory-stick}} 3. Yaddaş

$ free -h
               total   used   free   shared  buff/cache   available
Mem:            15Gi   5.1Gi  412Mi   210Mi      10Gi        9.8Gi
Swap:          4.0Gi     0B   4.0Gi
{{i:info}}

"free" azdır — narahat olmayın: Linux boş RAM-ı disk cache üçün istifadə edir. Baxılacaq sütun — available.

{{i:arrow-down-up}}

Swap-a aktiv yazma (vmstat-da si/so daim > 0) — real yaddaş çatışmazlığı.

{{i:trending-up}}

Memory leak: prosesin RSS-i günlərlə durmadan artır — ps -o pid,rss,etime,cmd --sort=-rss | head.

{{i:skull}}

OOM: journalctl -k | grep -i "out of memory". Kritik servisləri qorumaq: OOMScoreAdjust=-500 (systemd).

{{i:microscope}} 5. Dərin Analiz Alətləri

{{i:bug}}

strace -p PID -f -tt: proses hansı syscall-larda ilişib — məsələn, cavab verməyən DNS və ya kilidlənmiş faylda.

{{i:file-search}}

lsof -p PID: açıq fayllar, socket-lər; "too many open files" üçün ulimit -n və LimitNOFILE.

{{i:flame}}

perf top / perf record: CPU vaxtının hansı funksiyalara getdiyi; flame graph.

{{i:radar}}

eBPF (bcc, bpftrace): execsnoop, opensnoop, biolatency, tcpretrans — production-da təhlükəsiz müşahidə.
