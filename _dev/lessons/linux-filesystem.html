{{i:folder-tree}} Giriş: Linux-da Hər Şey Fayldır

Linux-da disk (/dev/sda), terminal (/dev/tty), proses məlumatı (/proc/1234), hətta təsadüfi ədəd generatoru (/dev/urandom) belə fayl kimi görünür. Fayl sisteminin quruluşunu və işləmə məntiqini bilmək — "disk dolub, amma heç bir böyük fayl görünmür" kimi problemləri dəqiqələrlə həll etmək deməkdir.

{{i:link}} 2. Inode, Hard Link və Symbolic Link

Inode faylın metadata-sını saxlayır: icazələr, sahib, ölçü, tarixlər, məlumat bloklarının yeri. Fayl adı isə sadəcə qovluqdakı "ad → inode nömrəsi" qeydidir.

ls -li report.txt             # birinci sütun — inode nömrəsi
stat report.txt               # bütün metadata
df -i                         # inode istifadəsi — 100% olarsa yer olsa belə fayl yaradılmır

ln report.txt report-hard.txt     # hard link: eyni inode, iki ad
ln -s /var/log/nginx logs         # symlink: yol göstəricisi, ayrıca inode
readlink -f logs                  # symlink-in son hədəfi

{{i:lightbulb}}

"Disk dolub, amma fayl yoxdur": silinmiş, lakin hələ proses tərəfindən açıq saxlanılan fayl yer tutmağa davam edir. lsof +L1 ilə tapın və prosesi restart edin.

{{i:search}} 3. find və du ilə Axtarış

du -xh --max-depth=1 / 2>/dev/null | sort -h | tail     # ən böyük qovluqlar
find /var -xdev -type f -size +500M -exec ls -lh {} \;  # 500 MB-dan böyük fayllar
find /var/log -name "*.gz" -mtime +30 -delete            # 30 gündən köhnə arxiv log-lar
find /home -type f -perm -o+w                            # hamının yaza bildiyi fayllar
find / -xdev -user olduser 2>/dev/null                   # silinmiş istifadəçinin faylları
find /etc -newer /tmp/marker                             # marker-dən sonra dəyişənlər
find . -name "*.conf" -exec grep -l "Listen 80" {} +     # məzmuna görə
locate nginx.conf                                        # indekslə sürətli axtarış (updatedb)

-xdev — başqa fayl sistemlərinə (məs. NFS, /proc) keçmə. -delete-dən əvvəl həmişə eyni əmri onsuz işlədib siyahıya baxın.

{{i:hard-drive}} 4. Mount və /etc/fstab

lsblk -f                          # disklər, bölmələr, FS tipləri, UUID
findmnt                           # mount ağacı
mount /dev/sdb1 /mnt/data
umount /mnt/data                  # "target is busy" → lsof +f -- /mnt/data

# /etc/fstab
# <cihaz>                                  <nöqtə>    <tip>  <seçimlər>                 <dump> <pass>
UUID=3f2a...-9c1d                          /data       xfs    defaults,noatime            0      2
//fs01/share                               /mnt/share  cifs   credentials=/root/.smb,_netdev  0  0
10.0.0.20:/export/backup                   /backup     nfs    defaults,_netdev,nofail     0      0

mount -a                          # fstab-ı yoxla — reboot-dan ƏVVƏL mütləq!
systemctl daemon-reload
{{i:triangle-alert}}

fstab-da səhv sistemin açılmamasına (emergency mode) səbəb ola bilər. Cihaz adı (/dev/sdb1) dəyişə bilər — həmişə UUID istifadə edin; şəbəkə diskləri üçün _netdev və nofail.

{{i:cpu}} 5. /proc və /sys

cat /proc/cpuinfo | grep "model name" | head -1
cat /proc/meminfo | head -5
cat /proc/loadavg
cat /proc/1234/cmdline | tr '\0' ' '    # prosesin tam əmri
ls -l /proc/1234/fd                    # prosesin açıq faylları
cat /proc/sys/net/ipv4/ip_forward      # 1 = routing aktivdir

sysctl net.ipv4.ip_forward=1           # müvəqqəti dəyişiklik
echo "net.ipv4.ip_forward = 1" > /etc/sysctl.d/99-router.conf   # daimi
sysctl --system

cat /sys/class/net/eth0/speed          # NIC sürəti
cat /sys/block/sda/queue/rotational    # 1 = HDD, 0 = SSD
