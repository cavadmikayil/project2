{{i:file-code-2}} Giriş: İnfrastruktur Kod Kimi

Portalda 40 klik ilə yaradılan VPC-ni başqa regionda eyni cür təkrarlamaq, kimin nəyi dəyişdiyini bilmək və ya silinəndə bərpa etmək demək olar ki, mümkün deyil. Terraform infrastrukturu mətn fayllarında təsvir edir: kod git-də saxlanılır, review olunur və istənilən vaxt eyni nəticə ilə tətbiq edilir.

{{i:target}} Declarative

"Nə olmalıdır" yazırsınız, "necə etməli" yox. Terraform fərqi özü hesablayır.

{{i:plug}} Provider-lər

AWS, Azure, Google, Kubernetes, Cloudflare, GitHub, hətta Cisco və Fortinet — 4000-dən çox.

{{i:git-fork}} OpenTofu

Terraform-un Linux Foundation altında açıq mənbəli fork-u; əmrlər eynidir (tofu).

{{i:workflow}} 1. Əsas İş Axını

terraform init        # provider-ləri yüklə, backend-i qur
terraform fmt         # kodu standart formata sal
terraform validate    # sintaksis yoxlaması
terraform plan        # nə yaradılacaq (+), dəyişəcək (~), silinəcək (-)
terraform apply       # planı təsdiqlə və tətbiq et
terraform destroy     # hamısını sil (lab bitəndə)
{{i:triangle-alert}}

plan-ı həmişə diqqətlə oxuyun. -/+ destroy and then create replacement — resurs silinib yenidən yaranacaq; bu, verilənlər bazası üçün məlumat itkisi deməkdir.

{{i:braces}} 2. HCL: VPC və Server

# main.tf
terraform {
  required_providers {
    aws = { source = "hashicorp/aws", version = "~> 5.0" }
  }
}

provider "aws" {
  region = var.region
}

variable "region" {
  type    = string
  default = "eu-central-1"
}

resource "aws_vpc" "main" {
  cidr_block = "10.20.0.0/16"
  tags       = { Name = "portal-vpc", env = "lab" }
}

resource "aws_subnet" "public_a" {
  vpc_id            = aws_vpc.main.id          # başqa resursa istinad = asılılıq
  cidr_block        = "10.20.0.0/24"
  availability_zone = "${var.region}a"
}

data "aws_ami" "ubuntu" {                       # mövcud resursu oxumaq
  most_recent = true
  owners      = ["099720109477"]                # Canonical
  filter {
    name   = "name"
    values = ["ubuntu/images/hvm-ssd-gp3/ubuntu-noble-24.04-amd64-server-*"]
  }
}

resource "aws_instance" "web" {
  count         = 2
  ami           = data.aws_ami.ubuntu.id
  instance_type = "t3.micro"
  subnet_id     = aws_subnet.public_a.id
  tags          = { Name = "web-${count.index + 1}" }
}

output "web_ips" {
  value = aws_instance.web[*].private_ip
}

Terraform istinadlardan asılılıq qrafı qurur: əvvəl VPC, sonra subnet, sonra instance — sıranı əl ilə yazmaq lazım deyil. Asılı olmayan resurslar paralel yaradılır.

{{i:database}} 3. State: Terraform-un Yaddaşı

terraform.tfstate — koddakı resursların real cloud ID-ləri ilə əlaqəsini saxlayır. State olmadan Terraform nəyi idarə etdiyini bilmir.

{{i:cloud}}

Remote backend: komandada state S3 + DynamoDB lock, Azure Storage və ya Terraform Cloud-da saxlanılır.

{{i:lock}}

Locking: iki nəfər eyni anda apply edib state-i pozmasın.

{{i:eye-off}}

Həssasdır: state-də parollar açıq mətnlə ola bilər — git-ə yazmayın, backend-i şifrələyin.

{{i:git-compare}}

Drift: kimsə portalda əl ilə dəyişiklik edəndə plan fərqi göstərir və geri qaytarmağı təklif edir.

terraform {
  backend "s3" {
    bucket         = "cavad-tfstate"
    key            = "portal/prod.tfstate"
    region         = "eu-central-1"
    encrypt        = true
    use_lockfile   = true
  }
}

terraform state list                      # idarə olunan resurslar
terraform import aws_vpc.main vpc-0abc123 # əl ilə yaradılmış resursu idarəyə götür

{{i:boxes}} 4. Modullar və Mühitlər

# envs/prod/main.tf
module "network" {
  source   = "../../modules/network"     # və ya registry: "terraform-aws-modules/vpc/aws"
  cidr     = "10.20.0.0/16"
  azs      = ["eu-central-1a", "eu-central-1b"]
  env      = "prod"
}

module "web" {
  source        = "../../modules/web"
  subnet_ids    = module.network.private_subnet_ids
  instance_type = "t3.small"
  min_size      = 2
}

Eyni modul dev və prod qovluqlarında fərqli dəyişənlərlə çağırılır — mühitlər strukturca eyni, ölçü və parametrlərlə fərqli olur.
