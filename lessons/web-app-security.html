Giriş: Firewall Tətbiqin Səhvini Düzəltmir

Firewall 443 portunu açıq saxlamalıdır — əks halda sayt işləməz. Buna görə hücumların böyük hissəsi elə bu açıq qapıdan, tətbiqin məntiqindəki səhvlərdən istifadə edir. OWASP (Open Worldwide Application Security Project) ən kritik veb risklərini OWASP Top 10 siyahısında toplayır. Bu dərs zəiflikləri müdafiəçi — developer və admin gözü ilə izah edir.

2. SQL Injection

İstifadəçi girişi SQL sorğusuna mətn kimi birləşdirilir və sorğunun məntiqi dəyişdirilə bilir.

# Python — ETMƏYİN: giriş birbaşa sorğuya yapışdırılır
query = "SELECT * FROM users WHERE email = '" + email + "'"
cursor.execute(query)

Email sahəsinə dırnaq işarəsi ilə başlayan xüsusi mətn yazılsa, sorğunun şərti dəyişir və bütün cədvəl qaytarıla bilər.

# Parametrləşdirilmiş sorğu (prepared statement)
cursor.execute("SELECT * FROM users WHERE email = %s", (email,))

# və ya ORM
User.objects.filter(email=email)

Parametr sorğudan ayrı ötürülür — verilənlər bazası onu heç vaxt SQL kodu kimi icra etmir. Əlavə olaraq: tətbiqin DB hesabına minimal icazə (yalnız lazım olan cədvəllər, DROP yox).

3. Cross-Site Scripting (XSS)

İstifadəçinin daxil etdiyi mətn səhifəyə HTML kimi yazılır və başqa istifadəçinin brauzerində skript kimi işləyir — sessiya oğurlanması, saxta forma.

Output encoding: çıxışda < → &lt;. Müasir şablon mühərrikləri (Jinja, React) bunu avtomatik edir — onu söndürməyin.

DOM-da: innerHTML əvəzinə textContent.

Content-Security-Policy başlığı — hansı mənbələrdən skript yüklənə biləcəyini məhdudlaşdırır.

HttpOnly cookie — JavaScript sessiya cookie-sini oxuya bilmir.

4. Broken Access Control və IDOR

Ən çox rast gəlinən risk. Nümunə: /api/invoices/1045 sizin fakturanızdır; URL-də rəqəmi 1046 edəndə başqasının fakturası açılırsa — bu IDOR-dur (Insecure Direct Object Reference).

# Hər sorğuda serverdə yoxlama: bu obyekt bu istifadəçiyə aiddirmi?
invoice = Invoice.objects.get(id=invoice_id, owner=request.user)   # başqasınınsa — 404

Düyməni gizlətmək icazə deyil — yoxlama həmişə serverdə, hər sorğuda aparılmalıdır. Standart: "default deny".

5. Təhlükəsizlik Başlıqları (Nginx)

add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
add_header Content-Security-Policy "default-src 'self'; frame-ancestors 'none'" always;
add_header X-Content-Type-Options "nosniff" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;
server_tokens off;

HSTS brauzeri yalnız HTTPS istifadə etməyə məcbur edir; frame-ancestors 'none' saytın başqa saytın içində gizli açılmasının (clickjacking) qarşısını alır; server_tokens off Nginx versiyasını gizlədir. Nəticəni securityheaders.com ilə yoxlayın.

6. Secure SDLC

  1. Dizayn: threat modeling — "burada kim nəyi səhv istifadə edə bilər?"

  2. Kod: code review, SAST (statik analiz — Semgrep, SonarQube).

  3. Asılılıqlar: SCA — Dependabot, npm audit, pip-audit.

  4. Test: DAST — işləyən tətbiqin öz test mühitində skanı (OWASP ZAP).

  5. İstismar: WAF, log-lar, monitorinq, bug bounty / məsul açıqlama siyasəti.

Təhlükəsizlik testlərini yalnız öz sistemlərinizdə və ya yazılı icazə ilə aparın. Praktika üçün qanuni laboratoriyalar: PortSwigger Web Security Academy, OWASP Juice Shop, DVWA.
