Giriş: Server Almaq Əvəzinə Kirayələmək

Ənənəvi IT-də yeni layihə üçün server sifariş edilir, həftələrlə gözlənilir, rack-a quraşdırılır və 5 il istifadə olunur. Cloud computing isə hesablama gücünü, yaddaşı və xidmətləri internet üzərindən, lazım olduğu an və istifadə etdiyin qədər ödəməklə (pay-as-you-go) almaq modelidir.

On-premises

Avadanlıq şirkətin öz data mərkəzindədir. Tam nəzarət, amma böyük ilkin xərc (CapEx) və uzun tədarük müddəti.

Public cloud

AWS, Microsoft Azure, Google Cloud. Resurs dəqiqələr içində yaranır, aylıq hesab gəlir (OpEx).

Hybrid

Bəzi sistemlər ofisdə, bəziləri cloud-da — real şirkətlərin əksəriyyəti belə işləyir.

1. Cloud-un 5 Əsas Xüsusiyyəti (NIST)

On-demand self-service: istifadəçi portal və ya API ilə resursu özü yaradır, heç kimə zəng etmədən.

Broad network access: xidmətlərə şəbəkə üzərindən istənilən cihazdan müraciət olunur.

Resource pooling: provayderin fiziki resursları çoxlu müştəri arasında paylaşılır (multi-tenancy).

Rapid elasticity: yük artanda resurs avtomatik artır, azalanda azalır.

Measured service: istifadə ölçülür və hesaba yazılır — CPU saatı, GB, sorğu sayı.

Scalability — sistemin daha çox yükü götürə bilməsi (vertical: daha güclü VM, horizontal: daha çox VM). Elasticity — bu artım və azalmanın avtomatik baş verməsi.

3. Yerləşdirmə Modelləri

Public

Resurslar provayderə məxsusdur, internet üzərindən çoxlu müştəriyə verilir. Ən sürətli başlanğıc, ən az ilkin xərc.

Private

Cloud texnologiyası yalnız bir təşkilat üçün — öz data mərkəzində (VMware, OpenStack) və ya ayrılmış hostinqdə. Tənzimləyici tələblər üçün.

Hybrid

On-premises + public cloud, aralarında VPN və ya ExpressRoute/Direct Connect. Məsələn, AD ofisdə, veb-sayt cloud-da.

Multi-cloud

Bir neçə public provayder birlikdə (AWS + Azure). Vendor lock-in riskini azaldır, amma idarəetməni çətinləşdirir.

4. Shared Responsibility Model

Cloud-da təhlükəsizlik provayder ilə müştəri arasında bölünür. Provayder cloud-un təhlükəsizliyinə, müştəri isə cloud-dakı hər şeyin təhlükəsizliyinə cavabdehdir.

Məlumat, istifadəçi hesabları və giriş icazələri həmişə müştərinin məsuliyyətindədir. Açıq qalmış S3 bucket-dan məlumat sızması provayderin yox, müştərinin səhvidir.

5. Cloud İqtisadiyyatı

CapEx → OpEx: böyük ilkin avadanlıq xərci yerinə aylıq əməliyyat xərci.

Economies of scale: provayder milyonlarla server aldığı üçün vahid qiyməti aşağıdır.

Agility: test mühiti 5 dəqiqəyə qalxır, iş bitəndə silinir — pul yalnız işlədiyi saatlar üçün.

Tag-lar və budget: hər resursa project, owner, env tag-ı verin, budget alert qurun — unudulmuş VM-lər ən çox pul yeyən şeydir.

Qiymət modelləri: on-demand (çevik), reserved/savings plan (1–3 il öhdəlik, ~70%-ə qədər endirim), spot (boş güc, 90%-ə qədər ucuz, istənilən an kəsilə bilər).

Egress: cloud-a məlumat yükləmək adətən pulsuzdur, cloud-dan çıxan trafik isə ödənişlidir.
