Giriş: Konteynerlərin Orkestri

Bir serverdə 3 konteyneri docker compose ilə idarə etmək asandır. 50 serverdə 500 konteyner olanda isə suallar yaranır: hansı konteyner hansı serverdə işləsin, server çökəndə nə olsun, yeni versiya fasiləsiz necə çıxarılsın? Kubernetes (K8s) bu işi avtomatlaşdıran açıq mənbəli orkestrasiya platformasıdır.

Declarative

Siz "3 nüsxə nginx:1.27 işləsin" yazırsınız, K8s faktiki vəziyyəti daim buna uyğunlaşdırır (reconciliation loop).

Self-healing

Çökən konteyner yenidən başladılır, ölən node-dakı pod-lar başqa node-a köçürülür.

İdarə olunan K8s

EKS (AWS), AKS (Azure), GKE (Google) — control plane-i provayder idarə edir.

2. Əsas Obyektlər

Pod: ən kiçik vahid; bir və ya bir neçə konteyner eyni IP və volume-u paylaşır. Pod-lar müvəqqətidir.

Deployment: pod-ların istənilən sayını və versiyasını idarə edir; rolling update və rollback.

Service: dəyişən pod-lar üçün sabit IP və DNS adı. Növləri: ClusterIP, NodePort, LoadBalancer.

Ingress / Gateway API: HTTP(S) trafikini host və path-a görə Service-lərə yönləndirir.

ConfigMap və Secret: konfiqurasiya və parollar image-dan ayrı saxlanılır.

Namespace: klasteri komandalar və mühitlər üzrə məntiqi bölür (dev, prod).

PersistentVolumeClaim: pod silinəndə qalan disk; StatefulSet verilənlər bazaları üçün.

DaemonSet: hər node-da bir pod — log agenti, monitorinq agenti.

3. Manifest: Deployment + Service

apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
  namespace: portal
spec:
  replicas: 3
  selector:
    matchLabels: { app: web }
  template:
    metadata:
      labels: { app: web }
    spec:
      containers:
        - name: web
          image: nginx:1.27
          ports: [{ containerPort: 80 }]
          resources:
            requests: { cpu: "100m", memory: "128Mi" }   # scheduler bu qədər yer axtarır
            limits:   { cpu: "500m", memory: "256Mi" }   # bundan artıq istifadə edə bilməz
          readinessProbe:
            httpGet: { path: /, port: 80 }
---
apiVersion: v1
kind: Service
metadata:
  name: web
  namespace: portal
spec:
  selector: { app: web }       # bu label-lı pod-lara trafik göndər
  ports: [{ port: 80, targetPort: 80 }]
  type: ClusterIP

Service pod-ları label selector ilə tapır. Klaster daxilində digər tətbiqlər ona web.portal.svc.cluster.local adı ilə müraciət edir.

4. kubectl Əmrləri

kubectl create namespace portal
kubectl apply -f web.yaml                 # yarat və ya yenilə (declarative)
kubectl get pods -n portal -o wide        # pod-lar, IP-lər, node-lar
kubectl get deploy,svc -n portal
kubectl describe pod web-7d9f8-abcde -n portal   # Events: niyə başlamır?
kubectl logs -f deploy/web -n portal
kubectl exec -it deploy/web -n portal -- sh

kubectl scale deploy/web --replicas=5 -n portal
kubectl set image deploy/web web=nginx:1.28 -n portal   # rolling update
kubectl rollout status deploy/web -n portal
kubectl rollout undo deploy/web -n portal              # əvvəlki versiyaya qayıt

kubectl port-forward svc/web 8080:80 -n portal         # lokal test
kubectl top pods -n portal                              # CPU/RAM (metrics-server lazımdır)
