Giriş: Veb Server Nə Edir?

Veb server brauzerdən gələn HTTP sorğularını qəbul edir və fayl (HTML, şəkil) və ya arxadakı tətbiqin cavabını qaytarır. Ən çox istifadə olunanlar: Nginx, Apache və Windows-da IIS. Nginx yüksək yük altında az yaddaşla çox bağlantı saxlaya bilir və tez-tez reverse proxy kimi istifadə olunur.

1. HTTP Əsasları

Metodlar

GET — oxu, POST — göndər, PUT/PATCH — yenilə, DELETE — sil.

Status kodları

2xx uğur, 3xx yönləndirmə, 4xx klient xətası, 5xx server xətası.

Portlar

HTTP — TCP 80, HTTPS — TCP 443.

2. Nginx: Statik Sayt (Server Block)

sudo apt install nginx

# /etc/nginx/sites-available/example.az
server {
    listen 80;
    server_name example.az www.example.az;
    root /var/www/example.az;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }

    access_log /var/log/nginx/example.access.log;
    error_log  /var/log/nginx/example.error.log;
}

sudo ln -s /etc/nginx/sites-available/example.az /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

Bir serverdə bir neçə sayt server_name ilə ayrılır (virtual host). nginx -t — dəyişikliyi tətbiq etməzdən əvvəl sintaksis yoxlaması; xətalı konfiqurasiya ilə reload saytı dayandırmasın.

3. Reverse Proxy və Load Balancing

Tətbiq (Node.js, Python, Java) lokal portda işləyir, Nginx isə internetdən gələn sorğunu ona ötürür — HTTPS, keş, sıxılma və limitləri öz üzərinə götürür.

upstream app_backend {
    server 127.0.0.1:3000;
    server 10.0.0.12:3000;      # ikinci tətbiq serveri — yük bölgüsü
}

server {
    listen 80;
    server_name app.example.az;

    location / {
        proxy_pass http://app_backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }
}

X-Forwarded-For olmadan tətbiq bütün istifadəçiləri 127.0.0.1 kimi görər. upstream-də bir neçə server varsa, Nginx sorğuları növbə ilə (round-robin) paylayır.

4. HTTPS: TLS Sertifikatı

  1. Domenin A qeydi serverin IP-sinə yönəlməli, 80 və 443 portları açıq olmalıdır.

  2. Let's Encrypt pulsuz sertifikat verir; certbot onu alır və Nginx konfiqurasiyasını yeniləyir.

  3. Sertifikat 90 gün etibarlıdır — certbot avtomatik yeniləmə taymerini quraşdırır.

sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d example.az -d www.example.az
sudo certbot renew --dry-run          # avtomatik yeniləməni yoxla
systemctl list-timers | grep certbot

# Sertifikatı yoxlamaq
openssl s_client -connect example.az:443 -servername example.az </dev/null 2>/dev/null | openssl x509 -noout -dates -subject

Sonuncu əmr sertifikatın kimə verildiyini və bitmə tarixini göstərir. Vaxtı keçmiş sertifikat istifadəçilərdə "Your connection is not private" xətası yaradır.
