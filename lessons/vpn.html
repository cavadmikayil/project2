Giriş: İnternet Üzərində Şəxsi Tunel

Bakı və Gəncə filialını birləşdirmək üçün xüsusi xətt (MPLS, leased line) bahadır. Hər iki ofisdə artıq internet var. VPN (Virtual Private Network) internet üzərində şifrələnmiş tunel qurur: paket başqa paketin içinə qoyulur, şifrələnir və qarşı tərəfdə açılır.

Məxfilik

Şifrələmə (AES) — yolda paketi tutan onu oxuya bilməz.

Bütövlük

Hash (SHA-256) — paket yolda dəyişdirilərsə aşkar olunur.

Autentifikasiya

Pre-shared key və ya sertifikat — tunelin qarşı tərəfi həqiqətən o cihazdır.

Anti-replay

Ardıcıllıq nömrələri — köhnə paketi təkrar göndərmək işləmir.

2. IPsec

IPsec tək protokol deyil, protokollar çərçivəsidir:

KomponentVəzifəsi
IKE (v1/v2), UDP 500Tərəfləri autentifikasiya edir, açarları razılaşdırır (Diffie-Hellman)
ESP (IP protokol 50)Şifrələmə + bütövlük + autentifikasiya — praktikada həmişə bu istifadə olunur
AH (IP protokol 51)Yalnız bütövlük və autentifikasiya, şifrələmə yoxdur; NAT ilə işləmir
NAT-T, UDP 4500ESP-ni UDP-yə bükür ki, NAT arxasından keçə bilsin

Tunnel mode

Bütün orijinal IP paketi şifrələnir və yeni IP başlığı əlavə olunur — site-to-site VPN-in standart rejimi.

Transport mode

Yalnız faydalı yük şifrələnir, orijinal IP başlığı qalır — adətən GRE over IPsec-də istifadə olunur.

3. GRE və DMVPN

GRE: sadə tunel — multicast (OSPF hello) və digər protokolları daşıyır, amma şifrələmir. Buna görə adətən IPsec ilə birlikdə istifadə olunur: GRE over IPsec.

DMVPN: hub-and-spoke dizaynda spoke-lar bir-biri ilə birbaşa, dinamik tunel qurur — 100 filial üçün 100 × 99 / 2 statik tunel yazmaq lazım deyil.

Təmiz IPsec (crypto map) yalnız unicast daşıyır, ona görə tunel üzərindən OSPF qonşuluğu qurula bilmir. GRE over IPsec və ya VTI (Virtual Tunnel Interface) bu problemi həll edir.

4. Remote Access VPN

Klientsiz (brauzer)

HTTPS portal vasitəsilə yalnız veb tətbiqlərə giriş. Quraşdırma tələb etmir, imkanları məhduddur.

Tam tunel klienti

Cisco Secure Client (AnyConnect) TLS/DTLS və ya IKEv2 ilə cihaza daxili IP verir — istifadəçi ofisdə olduğu kimi işləyir.

Split tunneling

Yalnız şirkət şəbəkələrinə gedən trafik tunelə daxil olur, internet trafiki birbaşa gedir. Bant genişliyinə qənaət edir, amma nəzarəti azaldır.

5. Laboratoriya: VTI ilə Site-to-Site IPsec

R1(config)# crypto ikev2 proposal PROP
R1(config-ikev2-proposal)# encryption aes-cbc-256
R1(config-ikev2-proposal)# integrity sha256
R1(config-ikev2-proposal)# group 14
R1(config)# crypto ikev2 policy POL
R1(config-ikev2-policy)# proposal PROP

R1(config)# crypto ikev2 keyring KR
R1(config-ikev2-keyring)# peer R2
R1(config-ikev2-keyring-peer)# address 198.51.100.2
R1(config-ikev2-keyring-peer)# pre-shared-key VpnKey!2026

R1(config)# crypto ikev2 profile IKE-PROF
R1(config-ikev2-profile)# match identity remote address 198.51.100.2 255.255.255.255
R1(config-ikev2-profile)# authentication local pre-share
R1(config-ikev2-profile)# authentication remote pre-share
R1(config-ikev2-profile)# keyring local KR

R1(config)# crypto ipsec transform-set TS esp-aes 256 esp-sha256-hmac
R1(config)# crypto ipsec profile IPSEC-PROF
R1(ipsec-profile)# set transform-set TS
R1(ipsec-profile)# set ikev2-profile IKE-PROF

R1(config)# interface Tunnel0
R1(config-if)# ip address 172.16.0.1 255.255.255.252
R1(config-if)# tunnel source GigabitEthernet0/1
R1(config-if)# tunnel destination 198.51.100.2
R1(config-if)# tunnel mode ipsec ipv4
R1(config-if)# tunnel protection ipsec profile IPSEC-PROF

R1(config)# router ospf 1
R1(config-router)# network 172.16.0.0 0.0.0.3 area 0

R2-də eyni konfiqurasiya əks ünvanlarla yazılır. Tunnel0 adi interfeys kimi davranır — üzərindən OSPF qonşuluğu qurulur və filial şəbəkələri avtomatik öyrənilir.

show crypto ikev2 sa
show crypto ipsec sa
show interface Tunnel0
show ip ospf neighbor

IKEv2 SA "READY" olmalıdır; show crypto ipsec sa-da encaps/decaps sayğacları artmalıdır — biri artıb digəri artmırsa, problem qarşı tərəfdədir.

Lab: Site-to-Site IPsec VPN

Məqsəd

İnternet üzərindən iki ofis arasında IKE/IPsec tunel qurmaq və yalnız ofislərarası trafiki şifrələmək.

Alət

Cisco Packet Tracer (securityk9)

Müddət

60 dəq · Çətin

Topologiya

 LAN 192.168.1.0/24 --- R1 (Gi0/1 203.0.113.2) ---- ISP ---- (Gi0/1 198.51.100.2) R3 --- LAN 192.168.3.0/24

Tapşırıqlar

  1. ISP üzərindən public IP-lər arasında əlçatanlığı təmin edin (default route-lar).

  2. Maraqlı trafik ACL-i: 192.168.1.0/24 → 192.168.3.0/24 (R3-də əksinə).

  3. ISAKMP policy (phase 1): AES 256, SHA, pre-share, DH group 14; crypto isakmp key.

  4. Transform-set (phase 2): esp-aes 256 esp-sha-hmac; crypto map ilə peer, transform-set və ACL-i birləşdirib xarici interfeysə tətbiq edin.

  5. LAN-dan LAN-a ping — ilk paket itə bilər (tunel qurulur). Sayğacların artdığını göstərin.

  6. LAN-dan internetə (ISP loopback) gedən trafikin şifrələnmədiyini izah edin.

Yoxlama

show crypto isakmp sa
show crypto ipsec sa
show crypto map
show access-lists 110

Uğur meyarları

ISAKMP SA QM_IDLE vəziyyətindədir.

#pkts encaps/decaps sayğacları ping ilə artır.

Yalnız ACL-ə düşən trafik tunelə girir.

Həll — əvvəlcə özünüz cəhd edin 
R1(config)# access-list 110 permit ip 192.168.1.0 0.0.0.255 192.168.3.0 0.0.0.255
R1(config)# crypto isakmp policy 10
R1(config-isakmp)# encryption aes 256
R1(config-isakmp)# hash sha
R1(config-isakmp)# authentication pre-share
R1(config-isakmp)# group 14
R1(config)# crypto isakmp key VpnKey!23 address 198.51.100.2
R1(config)# crypto ipsec transform-set TS esp-aes 256 esp-sha-hmac
R1(config)# crypto map VPN-MAP 10 ipsec-isakmp
R1(config-crypto-map)# set peer 198.51.100.2
R1(config-crypto-map)# set transform-set TS
R1(config-crypto-map)# match address 110
R1(config)# interface gi0/1
R1(config-if)# crypto map VPN-MAP
! R3 əks istiqamətdə: ACL 192.168.3.0 → 192.168.1.0, peer 203.0.113.2

Packet Tracer faylı (.pkt) verilmir — topologiyanı özünüz qurmaq labın bir hissəsidir.
