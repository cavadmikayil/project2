Giriş: Bir Fiziki Server — Çox Virtual Maşın

Əvvəllər hər xidmət üçün ayrıca fiziki server alınırdı və onların çoxu 10–15% yüklə işləyirdi. Virtualizasiya bir fiziki serveri bir neçə izolə olunmuş virtual maşına (VM) bölür: hər VM-in öz OS-i, CPU, RAM və diski var. Resurslar səmərəli istifadə olunur, yeni server dəqiqələr ərzində yaradılır.

1. Hypervisor Növləri

Type 1 (bare-metal)

Birbaşa hardware üzərində işləyir: VMware ESXi, Microsoft Hyper-V, Proxmox VE (KVM), XCP-ng. Data mərkəzinin standartı.

Type 2 (hosted)

Adi OS-in üzərində proqram kimi: VirtualBox, VMware Workstation. Laboratoriya və öyrənmə üçün ideal.

VM yaratmaq üçün CPU-da hardware virtualizasiya dəstəyi (Intel VT-x / AMD-V) BIOS-da aktiv olmalıdır. Linux-da yoxlamaq: egrep -c '(vmx|svm)' /proc/cpuinfo — nəticə 0-dan böyük olmalıdır.

3. Resursların Planlanması

vCPU: fiziki nüvələrdən çox vCPU vermək olar (overcommit), amma 3–4:1-dən yuxarı nisbət CPU gözləmə vaxtını (CPU ready) artırır.

RAM: RAM overcommit təhlükəlidir — host yaddaşı tükənsə, VM-lər swap-a düşür və çox yavaşlayır.

Disk: Thin provisioning yeri tədricən tutur (qənaət, amma datastore dolma riski); thick — yer əvvəlcədən ayrılır.

Guest tools: VMware Tools / qemu-guest-agent — sürücülər, düzgün söndürmə və performans üçün mütləq quraşdırın.

FunksiyaNə edir

High Availability (HA)Host sıradan çıxanda VM-lər digər host-larda avtomatik yenidən başlayır
Ortaq storageMigration və HA üçün VM diskləri bütün host-ların gördüyü storage-da olmalıdır (SAN, NFS, Ceph)

Snapshot backup deyil! O, orijinal diskə bağlıdır — disk itərsə snapshot da itir. Snapshot-u həftələrlə saxlamayın: delta faylı böyüyür, performans düşür və datastore dola bilər. Yeniləməni yoxladıqdan sonra snapshot-u silin (consolidate).

5. Virtual Şəbəkə

Host-un içində virtual switch var: VM-lərin virtual NIC-ləri ona, o isə host-un fiziki portlarına (uplink) qoşulur.

  VM1 (VLAN 10)   VM2 (VLAN 20)   VM3 (VLAN 20)
      │               │               │
  ┌───┴───────────────┴───────────────┴───┐
  │   Virtual switch (vSwitch / Linux bridge) │
  └───────────┬───────────────┬───────────┘
          uplink 1         uplink 2      ← NIC teaming
              │               │
        [ Fiziki switch — trunk port (VLAN 10,20) ]

VLAN teqləmə

Port group-a VLAN ID verilir; fiziki switch portu trunk olmalıdır — CCNA-dakı 802.1Q biliyi burada lazımdır.

Uplink ehtiyatı

İki fiziki NIC fərqli switch-lərə — biri düşəndə VM-lər şəbəkəsiz qalmır.

Management ayrı

Hypervisor-un idarəetmə interfeysi ayrıca management VLAN-da olmalıdır.
