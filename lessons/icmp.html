Giriş: Şəbəkənin Diaqnostika Dili

ICMP (Internet Control Message Protocol) IP-nin "xidməti" protokoludur: məlumat daşımır, əvəzinə xətaları və vəziyyəti bildirir. Port nömrəsi yoxdur — birbaşa IP paketinin içində (protokol nömrəsi 1) daşınır. ping və traceroute alətləri ICMP üzərində qurulub.

1. Əsas ICMP Mesajları

TypeAdNə vaxt göndərilir
8Echo Requestping sorğusu
0Echo Replyping cavabı
3Destination UnreachableŞəbəkə/host/port əlçatmazdır və ya ACL bloklayıb (code 13)
11Time ExceededTTL 0-a çatıb — traceroute məhz bundan istifadə edir
5RedirectRouter hosta daha yaxşı gateway göstərir

2. Ping Nəticələrini Oxumaq (Cisco IOS)

R1# ping 10.2.2.50
Type escape sequence to abort.

.!!!!
Success rate is 80 percent (4/5), round-trip min/avg/max = 1/2/4 ms

!Echo Reply alındı — uğurlu
.Timeout — cavab gəlmədi

Birinci paketin itməsi (.!!!!) adətən normaldır: router həmin anda ARP ilə növbəti hop-un MAC ünvanını öyrənir və ilk paket gözləmə müddətində atılır.

3. Traceroute Necə İşləyir?

  1. Birinci paket TTL = 1 ilə göndərilir. Birinci router TTL-i 0-a endirir, paketi atır və ICMP Time Exceeded qaytarır — beləcə onun ünvanı məlum olur.

  2. Növbəti paket TTL = 2 ilə gedir və ikinci router cavab verir.

  3. Təyinata çatana qədər TTL hər dəfə 1 artırılır. Təyinat "Port Unreachable" (Cisco/Linux, UDP) və ya "Echo Reply" (Windows tracert, ICMP) ilə cavab verir.

R1# traceroute 10.2.2.50
  1 10.0.0.2   1 msec  1 msec  1 msec
  2 10.0.1.2   2 msec  2 msec  1 msec
  3 10.2.2.50  3 msec  *       2 msec

* — həmin probe üçün cavab gəlmədi. Bir neçə sətir boyunca yalnız * * * görünürsə, paketlər adətən məhz o hop-dan sonra itir (marşrut yoxdur, ACL və ya firewall bloklayır).

4. Praktiki Əmrlər

ping 10.2.2.50 repeat 100 size 1500
ping 10.2.2.50 source Loopback0
ping
traceroute 10.2.2.50 numeric
R1(config-if)# no ip unreachables

100 ədəd 1500 baytlıq paket, müəyyən mənbə interfeysindən ping (qayıdış marşrutunu yoxlamaq üçün), parametrləri tək-tək soruşan genişləndirilmiş ping, DNS sorğusuz traceroute. Sonuncu əmr interfeysdə Unreachable mesajlarını söndürür (təhlükəsizlik üçün).

ping -n 10 8.8.8.8
ping -t 192.168.1.1
tracert 8.8.8.8
pathping 8.8.8.8
traceroute -I 8.8.8.8

Windows-da 10 ədəd ping, dayanmadan ping (Ctrl+C ilə dayanır), yolun izlənməsi və hər hop-da itki statistikası. Sonuncu Linux əmridir (-I ilə ICMP istifadə edir).

Lab: Ping və Traceroute ilə Nasazlığı Tapmaq

Məqsəd

Əlçatanlıq problemini ping, extended ping və traceroute nəticələrinə görə dəqiq hop-a qədər lokalizə etmək.

Alət

Cisco Packet Tracer

Müddət

40 dəq · Orta

Topologiya

 PC1 --- R1 (Gi0/1) 10.0.12.0/30 (Gi0/0) R2 (Gi0/1) 10.0.23.0/30 (Gi0/0) R3 --- Server
 192.168.1.0/24                                                        192.168.3.0/24

Ünvanlama cədvəli

CihazInterfeysIP / maska
R1Gi0/0 / Gi0/1192.168.1.1 /24 · 10.0.12.1 /30
R2Gi0/0 / Gi0/110.0.12.2 /30 · 10.0.23.1 /30
R3Gi0/0 / Gi0/110.0.23.2 /30 · 192.168.3.1 /24
PC1 / ServerNIC192.168.1.10 · 192.168.3.10 (gateway .1)

Tapşırıqlar

  1. Topologiyanı qurun və statik marşrutlarla tam əlçatanlıq təmin edin; PC1-dən Server-ə ping və tracert işlədin.

  2. R2-də R3-ə gedən marşrutu silin (no ip route 192.168.3.0 ...). PC1-dən yenidən ping: hansı cavab gəlir (Destination host unreachable yoxsa timeout) və kim göndərir?

  3. tracert ilə problemin hansı hop-da olduğunu göstərin.

  4. Marşrutu qaytarın, R3-də isə geriyə (192.168.1.0) marşrutu silin. Ping nə göstərir və niyə traceroute R3-ə qədər çatır, amma cavab qayıtmır?

  5. R1-də extended ping ilə mənbə interfeysini Gi0/0 seçib Server-ə 100 paket göndərin, size 1500 və df-bit sınayın.

Yoxlama

PC1> ping 192.168.3.10
PC1> tracert 192.168.3.10
R1# ping
Protocol [ip]:  Target IP address: 192.168.3.10  Repeat count [5]: 100
Extended commands [n]: y   Source address or interface: GigabitEthernet0/0
R1# traceroute 192.168.3.10 source gi0/0
R2# show ip route

Uğur meyarları

Marşrut yoxdursa router Destination unreachable qaytarır (Cisco-da U), geri marşrut yoxdursa — timeout (.).

Traceroute problemi dəqiq hop-a qədər göstərir.

Extended ping-də mənbə interfeysini seçməyin nə üçün vacib olduğunu izah edə bilirsiniz.

Həll — əvvəlcə özünüz cəhd edin 
R1(config)# ip route 192.168.3.0 255.255.255.0 10.0.12.2
R1(config)# ip route 10.0.23.0 255.255.255.252 10.0.12.2
R2(config)# ip route 192.168.1.0 255.255.255.0 10.0.12.1
R2(config)# ip route 192.168.3.0 255.255.255.0 10.0.23.2
R3(config)# ip route 192.168.1.0 255.255.255.0 10.0.23.1
R3(config)# ip route 10.0.12.0 255.255.255.252 10.0.23.1

Packet Tracer faylı (.pkt) verilmir — topologiyanı özünüz qurmaq labın bir hissəsidir.
