Giriş: Amazon Web Services

AWS 2006-cı ildən fəaliyyət göstərən ən böyük public cloud provayderidir və 200-dən çox xidmət təklif edir. Onların hamısını öyrənmək lazım deyil — real layihələrin 80%-i eyni 10–15 əsas xidmət üzərində qurulur. Bu dərsdə məhz o xidmətləri və aralarındakı əlaqəni görəcəyik.

Root user

Hesabı yaradan email. Yalnız billing və hesab ayarları üçün — dərhal MFA qoyun və gündəlik işdə istifadə etməyin.

IAM user / role

Gündəlik iş üçün məhdud icazəli hesablar. Serverlər və xidmətlər açar yox, role istifadə edir.

İdarəetmə

AWS Management Console (veb), AWS CLI, SDK-lar (Python boto3) və Infrastructure as Code (CloudFormation, Terraform).

1. Qlobal İnfrastruktur

AnlayışNədirNümunə
RegionCoğrafi ərazi; bir-birindən müstəqil bir neçə AZ-dan ibarəteu-central-1 (Frankfurt)
Availability ZoneAyrıca enerji, soyutma və şəbəkəsi olan bir və ya bir neçə data mərkəzieu-central-1a, 1b, 1c
Edge locationCloudFront CDN və Route 53 üçün istifadəçiyə yaxın nöqtələrYüzlərlə şəhərdə

Region seçərkən dörd sual verilir: qanunvericilik (məlumat hansı ölkədə qalmalıdır), latency (istifadəçilərə yaxınlıq), xidmətin mövcudluğu (yeni xidmətlər hər regionda olmur) və qiymət (regionlar arasında fərqlənir).

Yüksək əlçatanlıq üçün tətbiq ən azı iki AZ-a yayılır. Bir AZ-da yanğın və ya enerji kəsintisi olsa, digər AZ işləməyə davam edir.

2. Compute Xidmətləri

EC2: virtual serverlər. Instance type ailəsini göstərir: t3 (ümumi, burstable), m7 (balanslı), c7 (CPU), r7 (RAM).

AMI: EC2 üçün şablon — OS və əvvəlcədən quraşdırılmış proqramlar.

Auto Scaling Group: yükə görə EC2 sayını avtomatik artırıb-azaldır, sıradan çıxanı əvəz edir.

Elastic Load Balancing: ALB (HTTP/HTTPS, L7), NLB (TCP/UDP, L4) — trafiki sağlam instance-lara paylayır.

Lambda: server olmadan kod — hadisə gələndə işləyir, millisaniyə ilə ödənilir.

ECS / EKS / Fargate: konteynerlər üçün; EKS — idarə olunan Kubernetes.

Digər vacib xidmətlər: VPC (şəxsi şəbəkə), Route 53 (DNS), CloudFront (CDN), CloudWatch (metrika və log), CloudTrail (API audit logu), IAM (giriş idarəetməsi).

4. AWS CLI ilə İş

aws configure                      # Access key, region (məs. eu-central-1), output: json
aws sts get-caller-identity        # hansı hesab/istifadəçi ilə işləyirəm?

# EC2
aws ec2 describe-instances --query "Reservations[].Instances[].[InstanceId,State.Name,PublicIpAddress]" --output table
aws ec2 stop-instances --instance-ids i-0abc123def4567890

# S3
aws s3 mb s3://cavad-backup-2027                  # bucket yarat (adı qlobal unikal olmalıdır)
aws s3 cp report.pdf s3://cavad-backup-2027/reports/
aws s3 sync ./site s3://cavad-backup-2027/site --delete
aws s3 ls s3://cavad-backup-2027 --recursive --human-readable

# CloudWatch log-ları
aws logs tail /aws/lambda/my-func --follow

Kompüterdə uzunmüddətli access key saxlamaq əvəzinə aws configure sso (IAM Identity Center) istifadə edin — qısamüddətli açarlar avtomatik yenilənir.

5. Mini Lab: İki AZ-lı Veb Tətbiq

  1. VPC: 10.0.0.0/16, iki AZ-da public və private subnet-lər.

  2. ALB public subnet-lərdə, yalnız 443 portu internetə açıq.

  3. Auto Scaling Group private subnet-lərdə, minimum 2 EC2, CPU 60%-dən yuxarı olanda artır.

  4. RDS PostgreSQL Multi-AZ — yalnız veb serverlərin security group-undan 5432 portuna giriş.

  5. S3 — istifadəçi faylları; EC2 bucket-a IAM role ilə çatır (açarsız).

  6. CloudWatch alarm + budget alert; iş bitəndə bütün resursları silin.

Free Tier yeni hesablara məhdud pulsuz istifadə verir, amma NAT Gateway, Load Balancer və böyük instance-lar pulludur. İlk gün AWS Budgets-də 5–10 USD-lik alert yaradın.
