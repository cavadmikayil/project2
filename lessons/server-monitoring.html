Server Monitorinqi

Server · Əməliyyat
Giriş Metrikalar Alətlər Prometheus Xəbərdarlıqlar Dashboard Portal

Giriş: Problemi İstifadəçidən Əvvəl Görmək

Disk gecə saat 3-də 100% dolur, sayt səhər açılmır və ilk xəbər müştəri zəngindən gəlir. Monitorinq bunun əksidir: disk 85%-ə çatanda admin xəbərdarlıq alır və problemi heç kim hiss etmədən həll edir.

Metrics

Rəqəmlər zamanla: CPU %, RAM, disk, sorğu sayı, cavab müddəti.

Logs

Hadisələrin mətn qeydləri: xətalar, girişlər, sorğular.

Traces

Bir sorğunun mikroservislər arasında keçdiyi yol — harada ləngidiyini göstərir.

3. Prometheus + Node Exporter + Grafana

# compose.yaml — monitorinq stack-i
services:
  prometheus:
    image: prom/prometheus:v2.54.1
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
    ports: ["9090:9090"]
  node-exporter:
    image: prom/node-exporter:v1.8.2
    pid: host
    volumes:
      - /:/host:ro,rslave
    command: ["--path.rootfs=/host"]
  grafana:
    image: grafana/grafana:11.2.0
    ports: ["3000:3000"]

# prometheus.yml
scrape_configs:
  - job_name: node
    scrape_interval: 15s
    static_configs:
      - targets: ["node-exporter:9100", "10.0.0.11:9100", "10.0.0.12:9100"]

Node Exporter hər serverdə 9100 portunda CPU, RAM, disk, şəbəkə metrikalarını verir; Prometheus onları hər 15 saniyədən bir toplayır; Grafana (3000 portu) qrafikləri çəkir.

4. Xəbərdarlıq Qaydaları

# alerts.yml — disk 85%-dən çox, 10 dəqiqə davam edirsə
groups:
  - name: server
    rules:
      - alert: DiskAlmostFull
        expr: (1 - node_filesystem_avail_bytes{fstype!~"tmpfs|overlay"} / node_filesystem_size_bytes) * 100 > 85
        for: 10m
        labels:
          severity: warning
        annotations:
          summary: "{{ $labels.instance }}: disk {{ $value | humanize }}% doludur"

Hərəkət tələb edən xəbərdarlıq: hər alert-ə "nə etməli" (runbook) əlavə edin.

Alert fatigue: çox səs-küylü xəbərdarlıqlar ignor olunmağa başlayır — hədləri tənzimləyin, for: müddəti qoyun.

Kanallar: email, Telegram, Slack/Teams; kritik olanlar üçün növbətçi (on-call) sistemi.

5. Yaxşı Dashboard

  1. Yuxarıda ümumi vəziyyət: hansı xidmətlər işləyir, hansılar yox (yaşıl/qırmızı əvəzinə aydın mətn və ikon).

  2. Sonra istifadəçi təsiri: sorğu sayı, xəta faizi, cavab müddəti (p95).

  3. Aşağıda resurslar: CPU, RAM, disk, şəbəkə — problemin səbəbini axtarmaq üçün.

  4. Deploy və dəyişiklik anlarını qrafikdə işarələyin — "nə vaxtdan başladı?" sualına cavab.
