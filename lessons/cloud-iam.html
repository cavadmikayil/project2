Giriş: Cloud-da Yeni Perimetr — Identity

Ofisdə firewall hər şeyi qoruyurdu. Cloud-da isə hər resurs internetdən əlçatan API ilə idarə olunur, və sızmış bir access key bütün infrastrukturu silməyə kifayət edir. Buna görə cloud-da əsas təhlükəsizlik sərhədi identity-dir: kim, nəyə, hansı şərtlə çata bilər.

Authentication

Sən kimsən? Parol + MFA, SSO, qısamüddətli token.

Authorization

Nə edə bilərsən? Policy-lər və rollar.

Audit

Nə etdin? AWS CloudTrail, Azure Activity Log — hər API çağırışı qeydə alınır.

2. Policy-ni Oxumaq

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ReadReportsBucket",
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:ListBucket"],
      "Resource": [
        "arn:aws:s3:::cavad-reports",
        "arn:aws:s3:::cavad-reports/*"
      ]
    },
    {
      "Sid": "DenyOutsideEU",
      "Effect": "Deny",
      "Action": "*",
      "Resource": "*",
      "Condition": { "StringNotEquals": { "aws:RequestedRegion": ["eu-central-1", "eu-west-1"] } }
    }
  ]
}

ListBucket bucket-ın özünə (cavad-reports), GetObject isə obyektlərə (cavad-reports/*) aiddir — ona görə iki ARN yazılıb.

  1. Defolt olaraq hər şey qadağandır (implicit deny).

  2. Hər hansı policy-də explicit Deny varsa — nəticə Deny, Allow-lardan asılı olmayaraq.

  3. Əks halda explicit Allow varsa — icazə verilir.

3. Role-lar: Açarsız İcazə

Instance profile: EC2-yə role verilir, tətbiq SDK avtomatik müvəqqəti açar alır. Kodda və ya serverdə access key saxlanmır.

Cross-account: Security hesabındakı auditor Production hesabında ReadOnly role-u götürür.

OIDC federation: GitHub Actions secret-siz, qısamüddətli token ilə AWS/Azure-a deploy edir.

STS: müvəqqəti credential-lar 15 dəqiqə – 12 saat etibarlıdır, oğurlansa belə tez köhnəlir.

aws sts assume-role \
  --role-arn arn:aws:iam::222233334444:role/ReadOnlyAudit \
  --role-session-name cavad-audit

4. Azure RBAC

Azure-da icazə = security principal (kim) + role definition (nə) + scope (harada: management group, subscription, resource group, resurs).

# Developer qrupuna yalnız dev resource group-da Contributor
az role assignment create \
  --assignee-object-id <group-object-id> --assignee-principal-type Group \
  --role "Contributor" \
  --scope /subscriptions/<sub-id>/resourceGroups/rg-portal-dev

az role assignment list --scope /subscriptions/<sub-id>/resourceGroups/rg-portal-dev -o table

Entra rolları

Identity-ni idarə edir: Global Administrator, User Administrator, Helpdesk Administrator.

Azure RBAC rolları

Resursları idarə edir: Owner, Contributor, Reader, Virtual Machine Contributor.

PIM

Privileged Identity Management: admin rolu daimi yox, lazım olanda təsdiqlə və vaxt limiti ilə aktivləşir (just-in-time).

5. Qızıl Qaydalar

Least privilege: AdministratorAccess yox — işə lazım olan minimum. AWS IAM Access Analyzer istifadə olunmayan icazələri göstərir.

MFA hamı üçün, xüsusən root/Global Admin. Phishing-ə davamlı FIDO2 açarları ən yaxşısıdır.

Uzunmüddətli açar yoxdur: role, managed identity, OIDC. Açar lazımdırsa — rotasiya və Secrets Manager/Key Vault.

Break-glass hesabı: SSO işləməyəndə istifadə olunan, seyfdə saxlanan və girişi alert yaradan təcili hesab.

Access review: rüblük — işdən çıxanların və rol dəyişənlərin icazələrini təmizləyin.

Açarları git-ə yazmayın: GitHub secret scanning və gitleaks commit-dən əvvəl yoxlayır.
