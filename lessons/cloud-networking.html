Giriş: Cloud-da Öz Şəbəkən

Cloud-da yaradılan hər VM bir virtual şəbəkəyə qoşulur: AWS-də VPC (Virtual Private Cloud), Azure-da VNet (Virtual Network). Burada CCNA biliyiniz birbaşa işə yarayır: CIDR, subnetting, routing table, NAT, ACL — hamısı var, sadəcə router və switch yerinə API və portal ilə konfiqurasiya olunur.

CIDR blok

VPC üçün RFC 1918 aralığı: məs. 10.20.0.0/16. On-prem və digər VPC-lərlə üst-üstə düşməməlidir — sonra birləşdirmək mümkün olmur.

Subnet

AWS-də subnet bir AZ-a bağlıdır; Azure-da subnet region daxilində bütün zone-ları əhatə edir.

Route table

Hər subnet bir route table-a bağlanır. VPC daxilindəki local marşrut avtomatik mövcuddur.

AWS hər subnet-də 5 IP-ni rezerv edir (şəbəkə, router, DNS, gələcək istifadə, broadcast), Azure da 5. Deməli /24-də 251 istifadə oluna bilən ünvan qalır.

2. İnternet Girişi və Çıxışı

Internet Gateway (IGW): VPC-ni internetə bağlayır. Subnet-in route table-ında 0.0.0.0/0 → igw varsa, o subnet "public"dir.

NAT Gateway: private serverlər yeniləmə yükləyə bilsin, amma internetdən onlara bağlantı açılmasın — CCNA-dakı PAT-ın eynisi.

Elastic IP / Public IP: sabit public ünvan. İstifadə olunmayan public IPv4 ünvanlar da ödənişlidir.

Bastion / Session Manager: serverlərə SSH/RDP-ni internetə açmadan idarə etmək.

4. Şəbəkələri Birləşdirmək

Peering

İki VPC/VNet arasında birbaşa, şəxsi əlaqə. Transitive deyil: A–B və B–C peering-i A–C əlaqəsi yaratmır.

Transit Gateway / Virtual WAN

Onlarla VPC və ofis üçün hub-and-spoke mərkəzi router.

Site-to-Site VPN

Ofis firewall-u ilə cloud arasında IPsec tunel — internet üzərindən, dəqiqələrə qurulur.

Direct Connect / ExpressRoute

Provayderə ayrılmış fiziki xətt: sabit latency, yüksək bant, internetdən keçmir.

Private endpoint: S3, Azure SQL kimi PaaS xidmətlərinə trafik internetdən yox, VPC daxilindəki şəxsi IP üzərindən gedir.
